# Terminal architecture and protocol correctness

Research for the README/design of `go-tui-frame`, a Go library framing one external TUI. This document separates verified platform/protocol facts from proposed contracts. The initial research pass preceded runtime implementation and testing; later implementation follow-ups record their own inspection boundary. The user's scope includes transparent default input, optional capture, extensive observation, and a concise declarative consumer API.

**Confirmed scope:** the user subsequently selected Unix-like systems and macOS only; Windows is excluded. Windows/ConPTY findings remain below as comparative background, not planned support. Platform-selection gaps below describe the earlier research context and are superseded by this confirmation; the researched evidence is retained unchanged.

## What terminal architecture can contain an arbitrary child inside a frame?

### Takeaway

The design needs a child PTY/pseudoconsole, a stateful virtual terminal, and a compositor that owns the outer display. A PTY provides terminal I/O and job-control semantics; it does not restrict escape-sequence drawing to a rectangle. This is an architectural inference from the PTY and terminal control specifications, not an implemented guarantee. [Linux PTY semantics](https://man7.org/linux/man-pages/man7/pty.7.html), [XTerm controls](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).

### Cited Findings

- A Unix PTY pairs a master and slave. The slave behaves like a terminal; bytes written to the master become slave input. Terminal-generated signals target the slave's foreground process group. [Linux pty(7)](https://man7.org/linux/man-pages/man7/pty.7.html).
- Terminal operations include absolute cursor movement, full-display erase, full reset, margins/origin, alternate screens, and cursor/status queries. Scroll margins do not make all other operations local. [XTerm control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- Microsoft makes pseudoconsole hosts responsible for display and input. Its channel is UTF-8 even when the client uses another console encoding. [Microsoft pseudoconsoles](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles).
- Terminal parsing is modal across control strings, and a parser can intercept CSI/DCS/ESC/OSC operations. Async parser handlers can stall input processing while resize/reset continue changing state. [xterm.js parser API](https://xtermjs.org/docs/api/terminal/interfaces/iparser/).
- Terminfo describes terminal capabilities; applications consult this database to select operations. [ncurses terminfo](https://invisible-island.net/ncurses/man/terminfo.5.html).

### Inferences

- **Proposed engine:** child output enters a streaming parser/emulator; damage produces a child-local screen; a compositor draws that screen and frame through one outer-terminal writer. Outer input enters a separate router feeding the child input stream. This follows the distinct PTY and display responsibilities above. [PTY semantics](https://man7.org/linux/man-pages/man7/pty.7.html), [Microsoft hosting model](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles).
- **Rejected architecture:** prefixing rows or setting an outer scroll region cannot generally contain a program that changes the terminal state. Repainting the frame after letting child controls mutate the outer terminal would preserve neither a coherent child screen nor outer state. This conclusion follows from the independent control operations above. [XTerm controls](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- **Proposed terminal identity:** treat the child as connected to the library's virtual terminal. Select an existing `TERM` entry only after proving the emulator implements its advertised capabilities, or distribute a corresponding terminfo entry. Do not inherit the outer `TERM`, `TERM_PROGRAM`, or related capabilities without checking that they describe the child endpoint. Queries must agree with that virtual identity. [terminfo](https://invisible-island.net/ncurses/man/terminfo.5.html).
- **Proposed frame representation:** declarative header/footer/border/status configuration should produce layout and cell output; it should not let frame callbacks emit arbitrary outer-terminal bytes. Such bytes would create a second owner of the same terminal state. [Microsoft host responsibility](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles), [parser state changes](https://xtermjs.org/docs/api/terminal/interfaces/iparser/).

### Gaps

- No dependency has yet been selected or verified against the required complete protocol surface. A Go emulator accepting escape syntax is insufficient evidence of correct screen state, queries, modes, graphics, and input routing.
- Existing versus custom `TERM` identity, terminfo distribution, and what to do with unsupported operations require concrete decisions. These are not permission to reduce the user-requested compatibility scope.
- There is no justified claim of compatibility with every present/future terminal application or every terminal extension. The design can target arbitrary child executables through a documented, tested terminal capability contract.

## What does default input transparency mean, including mouse and optional capture?

### Takeaway

Uncaptured keyboard/paste bytes can be preserved on the route to the child terminal endpoint. Pointer positions must become child-local coordinates when a frame moves the child origin. Thus exact raw observation, default forwarding, and correct child semantics are compatible; universal byte-for-byte delivery of every event is not. This inference follows from coordinate-bearing mouse protocols and negotiated keyboard encodings. [XTerm mouse protocols](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html), [kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/).

### Cited Findings

- XTerm mouse tracking has press-only, press/release, highlight, drag, and all-motion variants; encodings include X10, UTF-8 1005, SGR 1006, urxvt 1015, and pixel 1016. X10 coordinates max at 223; 1005 at 2015. SGR distinguishes press `M` and release `m`. Focus 1004 reports `CSI I/O`; paste mode 2004 brackets data. [XTerm controls](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- Kitty keyboard enhancements distinguish modifiers, press/repeat/release, alternate key identities, and associated text. They negotiate flags, have query responses, and maintain separate normal/alternate-screen stacks. Legacy mode has collisions between physical keys and ambiguity around Escape. [kitty keyboard specification](https://sw.kovidgoyal.net/kitty/keyboard-protocol/).
- `modifyOtherKeys` and `formatOtherKeys` affect modified-key encoding; xterm's mapping has special cases and depends on terminal keyboard configuration. [XTerm modified-key documentation](https://invisible-island.net/xterm/modified-keys.html).
- Outer Unix raw mode disables canonical editing, echo, signal characters, and character transformations. Slave termios remains able to interpret interrupt/suspend/flow-control bytes according to the child's chosen settings. [Linux termios](https://man7.org/linux/man-pages/man3/termios.3.html).
- OpenTUI's embedded terminal demonstrates mode-aware forwarding, but its documented paste encoding sanitizes controls and translates newlines; pixel mouse 1016 is omitted. This is useful prior art, not a suitable fidelity guarantee for this project. [OpenTUI embedded terminal](https://opentui.com/docs/components/embedded-terminal/).

### Inferences

- **Proposed default:** no prefix key, pane shortcuts, automatic quit binding, Escape cancellation, or host-side Ctrl-C/Ctrl-Z interception. Read the outer terminal raw, preserve incoming byte slices, and let the child slave line discipline handle signal bytes when it is enabled. Kernel line-discipline processing is part of native terminal semantics; promise bytes written to the PTY, not identical bytes returned by every child `read`. [termios](https://man7.org/linux/man-pages/man3/termios.3.html).
- **Proposed preservation rule:** retain original input slices while a streaming classifier identifies only operations requiring handling. Do not decode the whole stream into a limited key enum and reconstruct it. Keyboard input from matching negotiated modes should stay unchanged; translation is necessary only where outer and virtual protocols differ. [kitty encoding](https://sw.kovidgoyal.net/kitty/keyboard-protocol/), [xterm encodings](https://invisible-island.net/xterm/modified-keys.html).
- **Proposed mouse rule:** subtract the child viewport's cell origin, preserve button/modifier/action, and encode under the child-selected protocol. Pixel mode requires a known pixel origin and cell geometry. Limits in legacy encodings cannot be solved by clamping without changing the event's meaning. [XTerm mouse protocols](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- **Proposed frame pointer rule:** frame positions have no valid child-local location. Expose the raw event and routing disposition to the consumer. Define frame hit-testing and gestures crossing the boundary explicitly; do not fabricate a click on the child's edge. This is a proposed geometry contract, derived from the coordinate-bearing protocols above. [XTerm mouse protocols](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- **Proposed optional capture:** consume only explicit bindings with an explicit action result. Preserve unmatched slices. Multi-key capture requires a declared timeout/replay policy because buffering changes input latency. Bracketed-paste content should remain opaque to shortcut matching. Legacy ambiguity means a capture cannot always distinguish the user's physical keys. [kitty keyboard limitations](https://sw.kovidgoyal.net/kitty/keyboard-protocol/), [OpenTUI paste handling contrast](https://opentui.com/docs/components/embedded-terminal/).

### Gaps

- Policy for pointer events outside the viewport and releases after a drag crosses the frame boundary needs an explicit API contract. Dropping or clamping all such events would silently conflict with broad forwarding expectations.
- Pixel geometry may be unavailable. Report that capability as unknown/unavailable rather than treating cells as pixels.
- An unknown coordinate-bearing input extension cannot simultaneously be forwarded untouched and guaranteed to use the correct translated origin. Discovery and explicit capability limits are necessary.
- The outer desktop/terminal may consume a physical shortcut before any bytes reach the library. Input observation concerns the actual terminal stream, not omniscient physical-device access.

## How should queries, modes, side effects, Unicode, and images be handled?

### Takeaway

The virtual terminal must own child-visible state and answer its state-dependent queries. Output extensions affecting the outer terminal or operating system need ordinary, documented routing policies; observing an operation does not imply passing it through raw. Unicode and images are part of the compatibility design, not decorations that can be omitted without changing scope. [XTerm queries](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html), [Unicode width guidance](https://www.unicode.org/reports/tr11/), [kitty graphics](https://sw.kovidgoyal.net/kitty/graphics-protocol/).

### Cited Findings

- Cursor reports use child coordinates; their byte forms can overlap modified function keys. XTerm offers state/attribute/size/terminfo queries and separate normal/alternate buffers; its normal buffer has saved lines while the alternate buffer does not. [XTerm controls](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- Unicode grapheme segmentation differs from rune counting. East Asian Width explicitly requires terminal-specific tailoring rather than providing a universal width algorithm. [Unicode UAX #29](https://www.unicode.org/reports/tr29/), [Unicode UAX #11](https://www.unicode.org/reports/tr11/).
- Kitty text sizing lets applications specify cell width, including grapheme handling, to avoid disagreements between terminal and application width calculations. [kitty text sizing](https://sw.kovidgoyal.net/kitty/text-sizing-protocol/).
- OSC 8 hyperlinks attach URI/id information to cells; link grouping may extend across independent screen updates. [OSC 8 author specification](https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda).
- iTerm2 documents title, cwd/host hints (including OSC 7), semantic shell marks, notifications, image/file transfer, and other extensions. These are emitted messages, not arbitrary internal application state. [iTerm2 escape codes](https://iterm2.com/documentation-escape-codes.html), [iTerm2 images](https://iterm2.com/documentation-images.html).
- OSC 52 accesses text clipboard data; kitty's OSC 5522 adds richer data types and permission/error responses. [kitty clipboard specification](https://sw.kovidgoyal.net/kitty/clipboard/).
- Kitty graphics separates transfers and placements, has ids, replies, deletions, clipping, scrolling, persistence, and quotas. File/shared-memory transports also exist; file failures must not reveal inaccessible host files. [kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/).
- DEC's sixel specification describes raster data, palette parameters, pixel positioning, scrolling mode, and cursor consequences; its screen-oriented behavior differs from ordinary text. [DEC VT330/VT340 graphics manual, HTML reproduction](https://manx-docs.org/mirror/vt100.net/docs/vt3xx-gp/chapter14.html).

### Inferences

- **Proposed query rule:** answer virtual screen position, size, modes, and identity from emulator state. Only proxy a query whose physical-terminal result remains valid for the child. Separate the engine's own outstanding queries from child queries and user input; do not globally discard every byte sequence that resembles a response. [XTerm query ambiguity](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).
- **Proposed mode rule:** track the child's requested input modes independently, then configure the outer terminal to deliver compatible input. Child normal/alternate switches must not switch away the frame's own outer screen. Kitty screen-specific stacks make blind mode-sequence relay especially inappropriate. [kitty keyboard stacks](https://sw.kovidgoyal.net/kitty/keyboard-protocol/).
- **Proposed text model:** cell contents retain grapheme text, display width/continuations, rendition/colors, and hyperlinks. Track cursor position/style/visibility, pending wrap, tabs, margins, saved state, both screens, and bounded configurable history. The width contract must identify supported Unicode/version behavior and rendering limitations. [Unicode grapheme rules](https://www.unicode.org/reports/tr29/), [terminal width tailoring](https://www.unicode.org/reports/tr11/), [OSC 8 cell metadata](https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda).
- **Proposed side-effect policies:** title and cwd requests become observable metadata; clipboard operations distinguish read/write; hyperlinks remain cell attributes; notifications, palette/font/window changes, file transfer, and remote-control extensions have explicit host-consumer policies. Implement allow, deny, or consumer handling as appropriate to the operation's real semantics. Preserve denied request bytes in observation, and provide protocol-defined failure responses where available. [iTerm2 operations](https://iterm2.com/documentation-escape-codes.html), [clipboard permission responses](https://sw.kovidgoyal.net/kitty/clipboard/).
- **Proposed graphics design:** supporting sixel, kitty graphics, and iTerm images entails retained image state, viewport translation/clipping, scroll/erase behavior, id isolation, replies, and outer-terminal rendering capabilities. Raw passthrough is not sufficient confinement. Graphics support must either be implemented and tested or be explicitly reported as unsupported; the user's scope does not authorize dropping it by default. [kitty graphics state](https://sw.kovidgoyal.net/kitty/graphics-protocol/), [DEC sixel cursor/scroll behavior](https://manx-docs.org/mirror/vt100.net/docs/vt3xx-gp/chapter14.html), [iTerm image protocol](https://iterm2.com/documentation-images.html).

### Gaps

- No emulator candidate is yet proven to satisfy all these protocols. Capability advertisement and input negotiation must match the selected backend's actual behavior.
- Outer and virtual Unicode/font shaping can disagree even when grapheme segmentation succeeds. Do not promise identical physical glyph appearance from a cell grid alone.
- Unknown output sequences should be observable with an unsupported-operation event. Whether consumer-approved passthrough is available needs a confinement contract; opaque passthrough cannot guarantee a stable frame.
- Final default clipboard/title/window/notification policies need design decisions, not generic security warnings or an extra approval workflow.
- The DEC HTML reproduction was searchable with its content but failed direct fetch; verify against the original manual before implementing sixel details.

## How do process setup, resize, job control, and cleanup differ by operating system?

### Takeaway

Unix requires real terminal session/foreground-process-group semantics; Windows requires native ConPTY hosting and separate lifecycle treatment. Resize is the child viewport size, and cleanup must distinguish root-process exit, stream drain, terminal restoration, and descendant ownership. [Linux controlling terminal](https://man7.org/linux/man-pages/man2/TIOCSCTTY.2const.html), [Microsoft ConPTY session setup](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session), [Go process waiting](https://pkg.go.dev/os/exec).

### Cited Findings

- Linux `setsid` establishes a new session/process group without a controlling terminal. `TIOCSCTTY` requires a session leader without an existing controlling terminal. `TIOCGPGRP`/`TIOCSPGRP` expose/select the terminal's foreground group. [setsid](https://man7.org/linux/man-pages/man2/setsid.2.html), [controlling terminal ioctls](https://man7.org/linux/man-pages/man2/TIOCSCTTY.2const.html), [foreground-group ioctls](https://man7.org/linux/man-pages/man2/TIOCGPGRP.2const.html).
- Apple's documented `login_tty` creates a session, selects the controlling tty, connects stdin/stdout/stderr, and closes the supplied descriptor; `forkpty` combines PTY allocation/fork/login setup. This is an archived Apple manual, not proof of every current macOS implementation detail. [Apple openpty/login_tty/forkpty manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/openpty.3.html).
- Linux winsize contains rows, columns, and pixel fields. Changing size sends `SIGWINCH` to the foreground process group; pixel fields are unused by the kernel. Apple's published XNU `TIOCSWINSZ` implementation compares/stores winsize and signals the tty's process group. [Linux TIOCSWINSZ](https://man7.org/linux/man-pages/man2/TIOCSWINSZ.2const.html), [Apple XNU tty.c](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/tty.c).
- ConPTY creation takes character dimensions and synchronous input/output streams; `ResizePseudoConsole` changes character dimensions. Microsoft recommends independently serviced channels to avoid blocked buffers and teardown deadlocks. [CreatePseudoConsole](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole), [ResizePseudoConsole](https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole), [ConPTY hosting](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session).
- Current `ClosePseudoConsole` sends `CTRL_CLOSE_EVENT` while clients can still produce output. On Windows 11 24H2 it returns immediately; older versions can wait indefinitely without output draining. It is supported from Windows 10 1809/Server 2019. [Current ClosePseudoConsole documentation](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole). The older setup guide's statement that clients are terminated on close is less precise. [Older setup guide](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session).
- Unix `kill` targets a process group with a negative group id. Go `CommandContext` defaults to killing its root process, not a managed terminal session; `Wait` waits for process exit and configured I/O copying. [Linux kill](https://man7.org/linux/man-pages/man2/kill.2.html), [Go os/exec](https://pkg.go.dev/os/exec).
- Windows Job Objects manage associated processes as a unit and can terminate them, with explicit child-association/breakaway rules. Console control events require a shared console; targeted Ctrl-C differs from targeted Ctrl-Break. [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [GenerateConsoleCtrlEvent](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent).

### Inferences

- **Proposed Unix setup:** attach all three standard descriptors to the same slave, establish the child session/controlling terminal/foreground group, set initial viewport winsize before execution, and close unused descriptors promptly. Connecting only pipes would alter native TTY behavior. [Linux PTY](https://man7.org/linux/man-pages/man7/pty.7.html), [controlling tty](https://man7.org/linux/man-pages/man2/TIOCSCTTY.2const.html), [Apple login_tty](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/openpty.3.html).
- **Proposed resize contract:** recompute child rows/columns from the frame layout; update emulator, backend winsize, and child-visible query answers consistently. Supply child pixel dimensions only from actual measured geometry. On Unix let the backend resize deliver its native foreground-group signal instead of redundantly signaling only the root PID. [Linux winsize](https://man7.org/linux/man-pages/man2/TIOCSWINSZ.2const.html), [Apple winsize signaling](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/tty.c), [Windows resize](https://learn.microsoft.com/en-us/windows/console/resizepseudoconsole).
- **Proposed cancellation contract:** distinguish graceful close, root signal, foreground-group signal, and forced owned-process termination. A shell may run a foreground group different from its initial group, and a detached descendant may escape process-group ownership. Do not describe root `Kill` as whole-tree cleanup. [foreground-group ioctls](https://man7.org/linux/man-pages/man2/TIOCGPGRP.2const.html), [kill targets](https://man7.org/linux/man-pages/man2/kill.2.html), [Go cancellation](https://pkg.go.dev/os/exec).
- **Proposed cleanup ownership:** the session owns backend descriptors, readers/writers, process waiting, mode changes, and terminal restoration. Restore outer termios and the known terminal modes the session changed, including on errors/cancellation. Suspend/resume must restore the outer terminal before stopping and reacquire/redraw on resume. Explicit capture remains optional. [termios restore primitives](https://man7.org/linux/man-pages/man3/termios.3.html), [ConPTY shutdown](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole).
- **Proposed Windows backend:** use ConPTY and native process/Job Object lifecycle where appropriate, without claiming Unix signal equivalence. Continue draining output and waiting for client exit after pseudoconsole close; close-return and root-exit are separate events. [ConPTY close](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole), [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

### Gaps

- User has not chosen an initial OS support commitment. Linux, macOS, and Windows require separate real-terminal verification; an API plan is not tested support.
- Arbitrarily escaped Unix descendants cannot be guaranteed to die from one process-group signal. Whole-descendant lifecycle scope needs explicit requirements and platform mechanisms.
- A frame leaving no positive-size viewport needs an explicit behavior (layout rejection, minimum geometry, or another user-selected policy), not guessed invalid winsize.
- Restoration after an uncatchable process kill or machine failure cannot be guaranteed by Go cleanup code. Exact restoration of unknown outer private modes likewise cannot be promised without a supported discovery/restoration mechanism.
- Current macOS process-inspection and suspend/resume details still need dedicated implementation-stage validation; the archived helper manual alone is insufficient.

## What child details are observable, and who owns callbacks and exact raw streams?

### Takeaway

Expose transport bytes, virtual-terminal state, process/backend events, and available OS metadata with provenance. Internal application models, original physical keystrokes, and the origin of writes merged into a single terminal stream are outside this black-box contract. Event callbacks must not acquire ownership of terminal I/O or block the core engine without an explicit backpressure contract. [PTY stream](https://man7.org/linux/man-pages/man7/pty.7.html), [stream reads](https://man7.org/linux/man-pages/man2/read.2.html), [parser blocking](https://xtermjs.org/docs/api/terminal/interfaces/iparser/).

### Cited Findings

- A successful `read` may return fewer bytes than requested. PTY transport is a byte stream rather than an application write/event-boundary recorder. [Linux read](https://man7.org/linux/man-pages/man2/read.2.html), [PTY master/slave](https://man7.org/linux/man-pages/man7/pty.7.html).
- Linux packet mode prefixes reads with control/data indicators and reports flushing/start/stop state. Its documented signals are not a universal notification feed for every termios mutation. [Linux TIOCPKT](https://man7.org/linux/man-pages/man2/TIOCPKT.2const.html).
- Linux `/proc/PID/cwd` is a link to the current working directory, with access checked using ptrace rules. `/proc/PID/stat` exposes process state, group/session/tty information and accounting, some guarded by permissions. [cwd](https://man7.org/linux/man-pages/man5/proc_pid_cwd.5.html), [stat](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html).
- Terminal cwd/host hints and shell marks exist as cooperative protocol output. [iTerm2 semantic integration](https://iterm2.com/documentation-escape-codes.html).
- Go process waiting/cancellation and Windows pseudoconsole draining concern distinct resources and completion conditions. [Go os/exec](https://pkg.go.dev/os/exec), [ConPTY close](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole).

### Inferences

- **Proposed observation streams:** retain exact outer input before decoding, exact child PTY/pseudoconsole output before parsing, and exact bytes successfully written to the child after capture/translation/replies. Keep these streams distinct. Mark generated query replies and translated input explicitly; associate transformations with source byte offsets. Consumers can then compare raw versus delivered bytes without losing unsupported operations. [stream reads](https://man7.org/linux/man-pages/man2/read.2.html), [PTY semantics](https://man7.org/linux/man-pages/man7/pty.7.html).
- **Proposed provenance:** monotonic session sequence numbers and per-stream offsets describe library observation order, not a perfect total order of external physical/process actions. Read chunk boundaries are arbitrary. On Unix capture begins after slave line-discipline output transformations; on Windows it begins after ConPTY's rendering/encoding conversion. Do not call it the child's original `write` stream. [read boundaries](https://man7.org/linux/man-pages/man2/read.2.html), [termios transformations](https://man7.org/linux/man-pages/man3/termios.3.html), [ConPTY encoding](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles).
- **Proposed snapshots/events:** executable/argv/initial cwd/env as launch configuration; PID and actual exit status; backend identity, viewport, modes, cursor, screen cells, scrollback, damage, colors, title/cwd hints, hyperlinks, image placements, bells, requests/replies, unsupported controls, and routing dispositions. OS metadata and cooperative hints carry their own source and availability/error state. [process API](https://pkg.go.dev/os/exec), [Linux process observations](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html), [cwd source](https://man7.org/linux/man-pages/man5/proc_pid_cwd.5.html), [cooperative hints](https://iterm2.com/documentation-escape-codes.html), [graphics state](https://sw.kovidgoyal.net/kitty/graphics-protocol/).
- **Proposed optional OS telemetry:** distinguish the launched leader, current foreground process group, and discovered descendants; expose runtime cwd, process state, CPU/memory accounting, and other verified native metadata per process where available. Include acquisition time, platform/source, permission errors, and identity-race handling. Configuration is not current runtime state, and OSC-reported remote cwd is a separate observation. Linux `/proc` and Windows Job Object accounting offer different native surfaces; macOS coverage remains to be researched. [Linux process state/accounting](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html), [runtime cwd](https://man7.org/linux/man-pages/man5/proc_pid_cwd.5.html), [foreground process group](https://man7.org/linux/man-pages/man2/TIOCGPGRP.2const.html), [Windows job accounting](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
- **Proposed immutable observation:** snapshots/byte payloads supplied to the consumer have explicit lifetime/ownership, preferably copies or durable records. A consumer must not be able to mutate the emulator through an observation object. This is a proposed API contract informed by stateful parser ownership. [parser state/lifecycle](https://xtermjs.org/docs/api/terminal/interfaces/iparser/).
- **Proposed callback boundary:** the engine serializes state mutations and child-input writes. Passive observation goes through a separate bounded dispatcher or consumer-read subscription; consumer commands are queued into the owner. Capture decisions are deliberately inline and must return promptly. Observers should never secretly become another terminal writer. [parser blocking consequences](https://xtermjs.org/docs/api/terminal/interfaces/iparser/), [independent I/O servicing](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session).
- **Proposed lifecycle events:** distinguish start failure, successful start, process exited, output drained/truncated, backend closed, cleanup completed, and final session result. The session owns one process wait and joins owned I/O workers. Define callback/subscription close ordering so no events arrive after final completion, and avoid invoking user callbacks while holding engine state locks. [Go Wait responsibilities](https://pkg.go.dev/os/exec), [ConPTY final output](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole).
- **Proposed recording contract:** lossless raw recording can block or fail if storage/consumer cannot keep up; live snapshots may coalesce changes with explicit sequence-gap indicators. Finite memory, permanently slow observers, guaranteed nonblocking I/O, and unconditional losslessness cannot all hold simultaneously. Declare this tradeoff instead of silently dropping bytes. [parser backpressure example](https://xtermjs.org/docs/api/terminal/interfaces/iparser/), [ConPTY blocked-channel consequences](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session).

### Gaps

- A shared PTY preserves native tty behavior while merging standard output/error and other writes to that tty. It cannot reliably label each byte as stdout/stderr or identify the original writer PID. Replacing one stream with a pipe changes the child endpoint and is a different supported mode, not an equivalent transparency implementation.
- Black-box terminal observation cannot infer the child's widget tree, editor buffers, selected object identities, application network state, or semantic intent. Cooperative integration may expose such details, but is an additional explicit protocol.
- OS process metadata has permission/platform/race limits; a launch PID need not be the current foreground job, and an emitted cwd hint can describe a remote shell rather than the local process cwd.
- Precise APIs for backpressure, observer failure, observer cancellation, snapshot lifetime, callback panic/error treatment, and what session completion waits for still need to be finalized. A callback that never returns cannot be forcibly stopped by ordinary Go goroutine cancellation.
- Sampling current slave termios is feasible through native APIs, but detecting every transient setting change is not established here. Do not promise complete termios history from packet mode alone.

- `KeyEncoder.SetOptFromTerminal` imports current child cursor/keypad modes, Alt-prefix behavior, modifyOtherKeys state 2, and Kitty flags. ## Native process follow-up (2026-10-01 19:40)

`internal/process` now samples OS state separately from launch argv/env/cwd. `Read(pid)` returns owned observations with `Field[T]{Value, Available, Source, Error}`; `List(sessionID)` inventories current native session members; `Groups(sessionID)` inventories distinct process groups for the runtime owner. Darwin enumeration uses `SysctlKinfoProcSlice("kern.proc.all")`; Linux enumerates numeric procfs directories.
